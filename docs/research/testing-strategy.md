# Reliable extension testing

Research date: 2026-10-22. Taylr changes arbitrary third-party pages. Controlled browser fixtures provide a reliable development gate; a deliberately difficult public-site catalog measures compatibility. Neither substitutes for the other. Commands and evidence interpretation live in [the testing guide](../testing.md); current site acceptance belongs in [the matrix](../site-test-matrix.md).

Historical permission context: the permission discussion and startup request counts below record the earlier optional per-origin design. The later installation grant and Site pause controls supersede that model; see [current decisions](../decisions.md#2026-10-22-installation-access-and-reversible-site-pause) and [current acceptance](../testing.md).

## Lasting decisions

- Grow coverage by **failure family**, not website count: recycled cards, nested controls, SVG/canvas, scrolling and reflow, portals, shadow DOM, iframes, SPA navigation, semantic identity, responsive layouts, private storage, worker restart, permissions and capture contention. Reproduce each new mechanism in the smallest real-browser fixture before fixing it; retain all six live checkpoints. [Playwright best practices](https://playwright.dev/docs/best-practices)
- Keep a fresh persistent Chromium context, temporary extension and profile per case. Extension sideloading requires a persistent context; sharing installations also shares rules and permissions. Pooling needs measured isolation proof before adoption. Tests never attach to personal browsers. [Extension testing](https://playwright.dev/docs/chrome-extensions), [fixture lifecycle](https://playwright.dev/docs/test-fixtures)
- Use bundled `channel: "chromium"` in unified headless mode by default. Headed mode is a diagnostic alternative, not an assumed protection workaround. Compare identical contracts and environments, preserving each result. [Browser channels](https://playwright.dev/docs/browsers), [Chrome Headless](https://developer.chrome.com/docs/automation-and-testing/headless)
- Build and preflight once before scheduling cases. Missing browser/build failures need one actionable environment artifact; a changed source tree must not silently test stale `dist`. Explicitly configure library-created context timeouts: Playwright Test's `use` settings do not configure them. [Context timeout settings](https://playwright.dev/docs/api/class-browsercontext)
- Classify at the failing phase using observed evidence. Challenges/main-document rate limits are access blocks; DNS/reset failures are environmental; missing or ambiguous declared components are contract failures; feature violations are product failures; broken drivers/artifacts are harness failures. Blocks and partial checkpoints never count as passes. Do not bypass authentication or protection.
- Readiness means observable application state within a bounded budget, not global network idle. Poll exact baseline invariants after reload/new-tab hydration; keep immediate Hide/Undo checks strict. Reacquire only the same declared component after a proved pointer miss or disconnected node. A connected-node picker mismatch must still fail.
- Keep report/checkpoint/screenshot evidence for every case, failure traces by default and full tracing opt-in. Manual tracing omits Playwright assertions, so phase/checkpoint JSON remains necessary. Separate build, harness, contract and environment identity. [Tracing API](https://playwright.dev/docs/api/class-tracing), [trace recommendations](https://playwright.dev/docs/best-practices)
- Use local fixtures during iteration, relevant canaries after cross-page changes, and the full catalog for release. Serialize top-level browser jobs because they share fixture port 5173; acceptance refuses an occupied port before cases launch and never inherits or terminates another owner. Worker concurrency belongs inside one owning job. Measure phase costs before increasing concurrency. Do not automatically retry the entire live catalog: retries amplify traffic and can conceal nondeterminism. [Retries](https://playwright.dev/docs/test-retries), [parallel workers](https://playwright.dev/docs/test-parallel)
- Targeted reruns may supplement a frozen audit only when build, harness, contracts and environment qualify. Reports preserve original runs, newest qualifying failures/blocks and rejected history. Mixed display modes, malformed candidates and incomplete passes are rejected; aggregation cannot make old-build evidence current.

## Preview and permission boundaries

Owned fixtures must assert actual component pixels, readable native resolution, cropping, aspect ratio and absence of the dock. Image presence alone is insufficient. Visual baselines depend on controlled browser/OS/fonts. Native CDP evidence capture avoids unrelated font-loading waits without altering site fonts or content. [Screenshot assertions](https://playwright.dev/docs/test-snapshots), [Page.captureScreenshot](https://chromedevtools.github.io/devtools-protocol/tot/Page/#method-captureScreenshot)

On Chromium 156, emulated `deviceScaleFactor: 2` changed page DPR but native `captureVisibleTab` still returned 1440 × 1000 pixels. `--force-device-scale-factor=2` yielded 2880 × 2000. Resolution tests must inspect actual backing dimensions; artificial upscaling cannot satisfy quality assertions.

The synthetic action bridge invokes the real handler but cannot establish Chrome's native `activeTab` gesture. Test-only exact-origin grants permit unattended injection; preview fixtures alone use broad grants in disposable copies. Production retains optional per-origin access and activeTab. A temporary zero-host-grant `_execute_action` shortcut failed to dispatch from Playwright renderer keyboard input in both display modes; the native-action diagnostic remains explicitly opt-in and unresolved. It is neither production permission coverage nor proof that activeTab fails. [activeTab and lifetime](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [action commands](https://developer.chrome.com/docs/extensions/reference/api/commands#action_commands)

Startup recovery has **eight** API-boundary contracts: transient injection, same-origin replacement, late and early cross-origin navigation, registration failure, denied injection, retry exhaustion and lost acknowledgement. They require one permission request, no automatic reload, preserved drafts where applicable, correct dock state and rules. The original seven-case probe had six failures and one existing pass; the additional early-origin race separately reproduced an unwanted destination dock. Recovery must preserve the original action's desired state, verify origin and pin mutations to the observed document, including before the first content injection. This addresses controlled mechanisms; the user's unspecified original sites remain unidentified. [Document-targeted scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting#type-InjectionTarget)

## Measured cost and display-mode limits

These historical runs used different web conditions and are not a controlled runtime benchmark:

| Audit | Coverage | Wall time | Evidence cost |
| --- | --- | ---: | --- |
| Original stored audit | 89 passed, 22 blocked | ~17 min, two workers | ~1.51 GB compressed live traces; ~1.37 GB from passes |
| `06-02-49-787Z-6e139f` | 78 passed, 22 blocked, 11 failed; all 111 attempted | ~17.5 min | 33 traces / 158.61 MB; 332.50 MB live artifacts total |

Trace storage fell about 89.5%, principally by discarding successful traces; **no runtime speedup was established**. Original blocked cases consumed 661 of 1,919 aggregate case-seconds (34%); refreshed blocks consumed 150.8 case-seconds. Refreshed summed phases were navigation 687.9 s, readiness 105.2 s, baseline 279.7 s, Hide 103.8 s, Undo 7.5 s, persistence 469.4 s, Restore 203.0 s, exit 32.9 s and finalization 8.4 s. These overlap across workers and are not wall time; screenshot work also occurs inside feature phases.

The matched three-contract experiment used Chromium 156.0.8078.4, Playwright 1.64.1 and a 1440 × 1000 viewport (`05-38-32-613Z-d71ad5`). Headless took 24.2 s: YouTube/Excalidraw passed, Canva blocked. Headed took 61.2 s: Excalidraw passed, YouTube exposed positional-selector persistence, Canva exposed an obsolete contract. Retained failure traces were 2.62 MB headless and 34.98 MB combined headed. This small sample establishes neither general speed nor protection-access superiority.

Later headed Canva evidence (`06-30-16-284Z-8ec32f`) showed the intended pointer point followed ~2 ms later by an unrelated trusted trajectory while refinement ran. Physical OS input versus another controller is unproven. These attempts are indeterminate under contaminated input; retries do not prove a fix, and the picker must not ignore genuine trusted user movement. Headless remains the isolated compatibility gate.

Incomplete applications need separate diagnosis from selector or picker defects. Historical `06-02-49-787Z-6e139f` traces showed Airbnb list skeletons with 18 unresolved resources (including its listings chunk); tldraw had an empty React root and 35 unresolved editor/auth resources. GeoGebra completed all 20 recorded requests but retained splash/early UI and logged a consent error whose causality is unproven. BBC rendered content yet hit DOMContentLoaded timeout with connection resets. Translate displayed “Getting translation...” with hidden source input and unresolved requests; its saved rule addressed only the clear button. None alone proves Taylr damaged the application.

GeoGebra later exposed an actual contract error: splash and initialized Algebra panels coexist. The intended component belongs inside `#ggbApplet`; the real graph remains required independently. Restoring that scope passed all three GeoGebra contracts. This is not grounds to substitute a splash component or claim a permanent website redesign.

## Current release evidence

The frozen 0.2.1 release audit (`14-45-59-704Z-a17d0a/headless`) attempted all 111 contracts: **94 passed, 17 externally blocked, no other failures, no stale or unrun cases**, and **31 fully verified sites**. It took **676.3 seconds including reporting** with two workers. Live artifacts total **155.64 MB**, including **17 traces / 9.46 MB**; successful traces were discarded. These costs are lower than the historical audits, but differing access conditions and feature outcomes prevent attributing the wall-time difference solely to harness changes.

Summed phases: navigation 355.4 s, readiness 87.0 s, baseline 142.4 s, Hide 54.6 s, Undo 7.3 s, persistence 329.4 s, Restore 182.9 s, exit 42.1 s, finalization 1.1 s. They overlap across workers and do not sum to wall time. The coherent deterministic gate (`14-43-42-383Z-d1f99b`) passed **63 cases in 2.0 minutes**, with live LeetCode and native action-shortcut checks explicitly opt-in. Occupied-server recovery is verified through the real child runner failing before sentinel launch. Current site outcomes and remaining access limitations are in [the matrix](../site-test-matrix.md).
