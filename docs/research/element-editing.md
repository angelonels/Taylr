# Element editing research

The closest precedent is a persistent visual site editor, with explicit drafts and reversible saves. A design debugger alone does not cover persistence, private sessions or concurrent tabs. The recording defines feature breadth; Taylr's interface is designed independently.

## Implementations studied

No code from these four implementations was imported. UIArc controls are covered separately below. ## Findings that affect behavior

**Text and layout need explicit boundaries.** VisBug's [text tool](https://github.com/GoogleChromeLabs/ProjectVisBug/blob/fef96fad0c54547637dd2bbdc326450027a906e7/app/features/text.js) enables `contenteditable` and removes editing attributes on exit. Its [flex tool](https://github.com/GoogleChromeLabs/ProjectVisBug/blob/fef96fad0c54547637dd2bbdc326450027a906e7/app/features/flex.js) forces `display:flex` for several operations. These are useful experiment shortcuts; adopting them in persistent customization could interfere with existing editors or unexpectedly restructure layout. Taylr uses a panel textarea for leaf text, excludes form/editable controls, preserves nested components, and leaves layout-mode controls out of the interface. Existing text nodes should retain their identity: assigning an element's `textContent` replaces its children. [DOM behavior](https://developer.mozilla.org/en-US/docs/Web/API/Node/textContent)

**Selection scope must be visible and conservative.** Stylebot's [selector module](https://github.com/ankit/stylebot/blob/e29fbf3a9f99ee76d788c4e1a387dc6939af727e/src/core/css/selector.ts) offers several scopes and detects generated identifiers; some choices deliberately match multiple components. Finder's [search](https://github.com/antonmedv/finder/blob/a8d83110d3d035e029c571b94965b629a10a469f/finder.ts) checks uniqueness and falls back to positional paths. Taylr targets one selected component, prefers semantic identity, checks exact matches, and retains Parent/Child refinement. Positional fallback remains vulnerable to site reordering; no claim of universal selector permanence is justified. Stylebot's [manual](https://stylebot.dev/manual/) also warns that generated selectors can stop working after updates.

**Undo is a transaction, not a stylesheet overwrite.** Stylebot's [undo stack](https://github.com/ankit/stylebot/blob/e29fbf3a9f99ee76d788c4e1a387dc6939af727e/src/apps/editor/store/undo-stack.ts) coalesces rapid changes by source and caps history at 100. Taylr's explicit Save naturally groups a draft. Worker-side property merging preserves unrelated edits; revision checks prevent Undo from replacing a newer save from another tab. Reset discards a property draft; Edits restores a saved rule. These actions need distinct labels and tests.

**Recovery must not become a mutation contest.** Stylus's [injector](https://github.com/openstyles/stylus/blob/b363a7e69d9cdb7b4976e0511f11c5a344cb4018/src/content/style-injector.js) observes root replacement and stops repeated style-order repair to avoid infinite loops. Its [API injection path](https://github.com/openstyles/stylus/blob/b363a7e69d9cdb7b4976e0511f11c5a344cb4018/src/background/style-via-api.js) caches per-frame styles and removes superseded CSS. Taylr retains its ordered user-origin CSS pipeline; text reapplication needs an independent bounded policy. Mutation observers can also observe changes made by another observer. [Observer contract](https://developer.mozilla.org/en-US/docs/Web/API/MutationObserver/observe)

**Computed values are an inspection baseline, not a source stylesheet.** `getComputedStyle()` returns resolved values, which can turn responsive lengths into pixels. Save only properties the user changed and retain entered units. Browser syntax validation supplements the shared property/value allowlist; syntactically supported CSS may still have no visible effect in the current layout. [Resolved values](https://developer.mozilla.org/en-US/docs/Web/API/Window/getComputedStyle), [CSS.supports](https://developer.mozilla.org/en-US/docs/Web/API/CSS/supports_static)

**Verification must separate declarations from layout.** Flex sizing and min/max constraints can make `getComputedStyle()` report a different used width or height even when the saved declaration wins. The shared site contract checks Typed OM’s computed value in those cases and records both computed and resolved dimensions. A missing declaration still fails; constraints never justify changing the selected target. After a text edit, verification follows the saved selector because the original text-based discovery locator may correctly stop matching. [CSS Typed OM specification](https://drafts.css-houdini.org/css-typed-om/), [computedStyleMap](https://developer.mozilla.org/en-US/docs/Web/API/Element/computedStyleMap)

**Isolation is limited by browser boundaries.** Chrome's scripting API requires permissions and distinguishes execution worlds, frames and CSS origins. Keep the inspector isolated, use USER-origin declarations for reliable overrides, and avoid requesting broader access for convenience. Closed shadow roots, iframe contents and canvas internals are distinct capabilities, not ordinary DOM editing. [Chrome scripting API](https://developer.chrome.com/docs/extensions/reference/api/scripting)

## Wider comparison

| Reference                                                                                       | Useful precedent                                                                                     | Deliberate boundary                                                                          |
| ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| [uBlock Origin picker](https://github.com/gorhill/uBlock/wiki/Element-picker)                   | Preview before creating a persistent filter; refine depth/specificity; distinguish temporary removal | Hide shares selection and reversible rules with Edit. No network-blocking engine.            |

| [CSS Pro change tracking](https://docs.csspro.com/editing/handling-css-changes)                 | Group changes by element; show what changed; copy/export workflows                                   | Keep local Save, Undo and Rules focused. Sharing/export is separate future work.             |

| [Amino](https://amino.dev/)                                                                     | Persistent styles with page/domain scope and disable switches                                        | Exact origin scope and local/private storage; no cloud account or sync.                      |
| [Live CSS Editor](https://www.livecsseditor.com/)                                               | Immediate feedback and movable editor                                                                | Explicit Save keeps experiments reversible.                                                  |
| [Arc Boosts](https://start.arc.net/paint-the-internet)                                          | Browser customization as a first-class tool                                                          | High-level product reference only; no source implementation inspected.                       |

Product pages establish advertised behavior, not reliability. Issue reports identify risks, not independently reproduced defects: VisBug has requests concerning [click suppression](https://github.com/GoogleChromeLabs/ProjectVisBug/issues/648) and [overlay isolation](https://github.com/GoogleChromeLabs/ProjectVisBug/issues/645). Those risks become Taylr tests rather than assumptions about upstream quality.

## Acceptance work

- Live preview, property reset, Cancel, Save, reload, new tab, Pause/Resume, Restore and integrated Hide/Undo must preserve unrelated page behavior.
- All controls need fixture coverage; public-site contracts exercise every exposed property on real components, with explicit applicability for text and layout-dependent gaps. Retain nearby elements and exact target identity through reload/replacement.
- Test retained text-node identity, nested controls, hostile CSS, late replies, concurrent saves, stale Undo, site text replacement and observer contention.
- Test scroll containment, always-reachable commit actions, keyboard selection, narrow/short viewports, zoom, reduced motion and visible glass over varied backgrounds.
- Keep verified results in the site matrix. Authentication, consent, CAPTCHA and unavailable content remain blocked coverage; future capabilities remain planned.

## UIArc controls

The public [UIArc repository](https://github.com/kuratlielia/arc-library/tree/7156a0c582197942e8f1e0c0614dec2bd284f653) was cloned and studied separately. Its free Button, ActionButton, Input, Textarea, Select, Accordion and ColorPicker components use the MIT license (© 2026 Elia Kuratli); Pro components are excluded. Taylr adapts those controls in `src/dock/ui/`, with the complete notice shipped in the extension build. Select uses a native non-modal popover; Accordion retains Radix semantics. ColorPicker keeps the upstream color math and hue-preserving state, with a native top-layer shell and transient presets.

The action-button pending/success lifecycle is useful, including retaining keyboard focus during saves. Its width measurement, blur animations and per-word field-message animation add unnecessary work to a narrow, frequently edited inspector. Taylr instead fixes the commit area's width, animates only opacity/transforms, keeps errors directly associated with fields and suppresses pointer motion for keyboard input. The custom floating shell remains translucent and isolated in Shadow DOM; UIArc's page-level theme variables are not written onto visited sites.
