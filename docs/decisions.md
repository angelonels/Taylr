# Foundation decisions

## 2026-10-21: Hide, first

The first release is a browser instrument: select an element, hide it, remember it on later visits, and reverse the action. The Arc research chat informed the interaction; the entire Boosts feature set is outside this milestone. Bulk matching of related elements and visual restyling are deferred.

TypeScript + Vite + Manifest V3 underpin the extension. The floating dock uses React and Tailwind at the user’s explicit request. React and Motion load only when the toolbar action is invoked; rule restoration and the picker controller remain framework-free. No server, account, telemetry, or remote data store is needed.

Rules belong to an exact origin (scheme, hostname, port), across its paths. The initial design requested optional site permission from the toolbar gesture; the installation grant below supersedes that permission model. Dynamic content scripts restore rules on later visits. Storage stays local. The background worker is the single writer to avoid lost updates across tabs. Ordered profile broadcasts own live state; mutation replies confirm the operation and its created ID, but cannot overwrite a newer state. Initial reads are ignored if a newer live update arrived during initialization.

Hiding uses a stylesheet rather than removing nodes or rewriting inline styles. This preserves the site's DOM ownership, naturally handles newly inserted matching elements, and lets Restore reveal the site's own styling. It cannot prevent network loading and is not an ad blocker or privacy boundary.

Selectors favor unique semantic attributes (including product identity and landmark roles), then non-generated IDs and an exact structural path. UUID/React render identifiers cannot be persistence anchors. Combinations of semantic attributes precede child-link anchoring: a product identifier may also exist on a nested faceout, while its role identifies the card. Repeated cards can use their own unique link through `:has()` to preserve identity when neighbors are inserted. Recognized attribution parameters (UTM/click IDs and listing impression/search IDs) do not identify content; link selectors ignore them, preserve other query tokens with parameter boundaries, and retain fragments. Arbitrarily dropping a query string would merge different videos or content variants. Observed YouTube `pp` impression values are ignored only on `youtube.com`/`www.youtube.com` `/watch` links with a video ID; video, playlist, timestamp and fragment identity remain intact. A rule targets one element at creation. Structural paths can drift after a redesign or reordered list; they cannot promise to identify the same conceptual item forever. Broad matching is deferred rather than silently hiding related content. Shadow-root interiors and iframe interiors are outside this first milestone. A unique iframe element itself can be hidden from its parent page.

The floating tool never reserves sidebar width: doing so changes responsive website layouts and can remove the intended target. React renders inside a Shadow DOM manual popover in the browser top layer. Visible Cancel/Done, Close, Undo and Escape make selection reversible. A grip supports bounded drag, edge switching and keyboard movement. Motion supplies interruptible drag values and release springs; reduced motion removes travel. Marketing belongs to a future landing page.

The old panel inferred “protected” when an active tab URL was unavailable. The action uses the tab supplied by Chrome directly and checks current host access. Ordinary HTTPS pages such as LeetCode are not classified as protected. Website login/security challenges remain separate from Chrome-restricted pages and cannot establish application-level coverage.

Toolbar opening checks existing host permission without requesting a new grant. Immediate injection is independent of persistent-script registration, pinned to a document, and retried once only for a document/context race on the same origin. Each explicit action has one desired open state; recovery cannot toggle an already opened toolbar closed. Cross-origin navigation requires a fresh action. Automatic page reloads would discard unsaved work, so startup never performs or prescribes one as a catch-all.

Selection geometry follows layout changes. Parent traversal remembers the original child. Button glyphs/labels target the control by default; explicit Child refinement can still select its graphic. Only hierarchy refinement preserves an ancestor on a later click. Trusted native input is required for picker keyboard/pointer events and dock mutations; synthetic page events cannot create rules. Late replies cannot transfer Undo ownership to a new session.

Cancel/Done stops choosing more components and abandons a pending preview before its storage mutation begins. A mutation already sent to the worker may finish; its saved rule remains reversible through Rules. Explicit Parent/Child refinement survives website-driven focus changes; native Tab deliberately hands selection to keyboard focus. A focus-driven selection invalidates the pointer cache so returning to the same component after Undo retargets correctly. Keyboard movement and activation are immediate, while pointer drag release can settle with a spring.

Incognito uses Chrome split mode with a separate `private-site:` namespace in session storage. Private rules survive reloads and new private tabs, but are memory-only and clear on browser restart or extension reload. Regular rules remain in local storage. Separate keys prevent the two workers from overwriting each other. Content scripts receive origin-scoped profile messages from the worker; session storage is not exposed to untrusted content contexts.

Undo records the exact ID returned by its own add request. Each injected controller belongs to its document and origin; profile broadcasts remain authoritative. Public-site tests refuse nonempty test profiles before taking ownership and cleaning up. Each case owns a disposable browser.

Automated testing moved to disposable Playwright Chromium at the user’s request. No personal-profile connection or permission broker remains. Most temporary test copies narrow host access to the exact test origins; the site-access acceptance case keeps the generated production host grant to verify installation behavior. The catalog selects modern sites and multiple component types for rendering/interaction difficulty, rather than using site count as a proxy for coverage.

Link identity preserves query values because they may identify content. The observed Flipkart product URL shape is a narrow exception: when the product path and SKU are present, observed impression/session/page-attribution values (`iid`, `ssid`, `ppt`, `ppn`) are omitted; other parameters remain. The `ppt`/`ppn` exception follows captured evidence of those values changing while the same product and listing IDs remain; no official definitions for these two keys were found. Product/listing IDs and every other query value remain part of identity. Those names retain their meaning on other origins. Stable dropdown semantics (`aria-haspopup`) take precedence over generated render IDs. Controlled E2Es retain distinct variants and unrelated query identities through reload/reordering. [Flipkart product identity reference](https://affiliate.flipkart.com/api-docs/af_prod_ref.html)

## Component previews

Rules show cropped pixels of the component before hiding. Satori renders layouts supplied by an application; it cannot reproduce arbitrary third-party DOM, video, canvas, or fonts accurately. Native Chrome capture is appropriate here. Only the visible crop is encoded as a bounded WebP and stored with the rule; the full screenshot is transient in worker memory. The active tab, URL and originating document are checked around capture to avoid capturing a different page. Captures are queued within Chrome’s rate limit and time-bounded; denied or unusable pixels fall back to a bounded text preview. Native detail is preserved within a 1024 × 768 / approximately 256KiB image budget, using adaptive encoding for detailed content. The dock is hidden only during the native capture rather than during quota waits. Storage pressure retries the new rule without its optional preview. Private previews use the same session-only partition as private rules.

Native PNG decoding uses a preallocated byte array and indexed copy to avoid per-byte iterator/callback overhead on large screenshots; the bounded capture deadline and pixel budget remain unchanged.

The selected node must remain connected with unchanged bounds, scroll position and viewport throughout capture. Reflow, scrolling or zoom discards the optional preview without cancelling Hide; a crop from a former position could otherwise retain unrelated content.

A canvas displays decoded preview pixels so a site's restrictive img-src policy does not block a data-image element. The preview is a historical visual aid; it does not imply the site still has the same content. Partially visible components are marked accordingly. No screenshot leaves the device.

## Quality gates

Oxlint treats correctness, promise handling, React hooks and selected accessibility rules as errors, with zero allowed warnings and unused suppression checks. Type-aware lint complements TypeScript rather than replacing it. The automatic JSX runtime does not require a React global. Chrome callback listeners and deliberate CSP-safe canvas rendering have narrow documented exceptions. Broad assertion bans and mandatory returned values are unsuitable for Chrome's untyped storage/message boundary and void callbacks; explicit validation guards persisted preview input instead.

Static dock styling lives in Tailwind compositions in `src/tailwind.css`; bespoke material shadows, Shadow DOM resets and platform preference rules retain CSS where utilities would obscure intent. CSS pixel spacing avoids inheriting a host site's root font scale.

See [testing research](research/testing-strategy.md) for test tiers and outcome semantics, and [preview research](research/component-previews.md) for capture alternatives, confirmed failures and storage/privacy constraints.

## 2026-10-22: Vertical floating panel and continuous verification

The horizontal dock becomes a vertical floating panel so tools have a clear reading order and room to grow. It remains an overlay, movable and bounded by the visible viewport, rather than Chrome's width-reserving side panel. Rules and selection details belong with the tools they support. The panel uses smoked charcoal glass, neutral high-contrast actions and coral selection feedback. This supersedes the earlier iris palette. System fonts, visible labels, immediate keyboard actions, reduced motion, solid reduced-transparency surfaces and forced-colors support remain product constraints.

The old `.commandcode` design notes duplicated these decisions and contained obsolete styling. Product constraints now live here; generated design audits do not belong in the source tree. Rule previews still show actual local component pixels with associated labels and Restore actions, support keyboard inspection, and fall back to readable text when capture is unavailable. Preview failure never blocks Hide.

GitHub Actions runs type checks, lint, formatting and deterministic disposable-Chromium acceptance on pushes to `main` and pull requests. The existing test wrapper builds the extension once before browser cases, so evidence and the downloadable unpacked extension describe the same source. Two isolated workers keep the default gate modest; npm downloads and version-keyed browser binaries are cached. Superseded runs are cancelled. Reports, traces and build diagnostics remain downloadable for seven days, and successful verified extension builds for fourteen days. Live canary/catalog checks require an explicit manual workflow choice; external access blocks remain incomplete verification. This delivers a testable extension artifact without publishing to the Chrome Web Store.

## 2026-10-22: Installation access and reversible site pause

Required HTTP/HTTPS host permissions replace per-site optional permission prompts at the user's request. Chrome grants this access during installation; an older installation may require approval of the expanded grant on update. Opening the tool checks existing permission and never requests a per-site grant. Browser-withheld access stays withheld. Dynamic restoration still registers only after an explicit first opening on an origin; an all-site grant does not eagerly inject the picker or React into every website. [Chrome permission declarations](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions).

The Site panel action contains Pause site, Resume site and Chrome access settings. Pause is an application setting, not a browser permission revocation: Chrome's permissions API cannot subtract an origin from a required wildcard grant. Chrome access settings opens the extension's browser settings for actual access control. [Chrome Permissions API](https://developer.chrome.com/docs/extensions/reference/api/permissions).

The pause flag belongs to the exact-origin Site profile beside its preserved rules, using the same regular/local and private/session partitions. Pausing stops selection, reveals hidden elements across open same-origin tabs and rejects new Hide writes. The lightweight controller stays registered and reads the pause flag without applying hiding rules. Chromium shares its user-script manager between regular and private contexts, so unregistering an origin for private Pause could disrupt regular restoration. Resume reapplies saved rules, including in tabs opened while paused. Other origins and the other privacy partition remain independent. [Chromium shared script manager](https://raw.githubusercontent.com/chromium/chromium/main/chrome/browser/extensions/chrome_extension_system.h).

## 2026-10-23: Per-site dark mode

Dark mode is an explicit Site profile flag, off by default. The existing single writer and ordered profile broadcasts own it, alongside preserved Hide rules and Pause. Regular/local and private/session storage remain separate. Pause turns off both hiding and recoloring while preserving the requests. Forced colors temporarily disables page recoloring without changing the saved request. Frequent toggle actions have immediate feedback and add no page-wide color animation; native site transitions still settle normally.

Dark Reader's pinned MIT browser engine supplies role-aware dynamic CSS, bundled locally and injected only after a saved dark-mode request. The picker/controller remains about 13KiB; React/Motion and the roughly 109KiB theme bundle load separately. No remote code, downloaded site-fix feed, screenshot analysis, global inversion filter, or custom per-node color compiler is introduced. The current photo/canvas fixture compares actual rendered interior pixels, and forced colors, media, Hide, cross-tab persistence and reversibility are E2E contracts.

The embedded API normally wraps native Chrome messaging and loses Promise return values. A lexical vendor bus at build time isolates it from Taylr's native IPC. Two additional guarded adaptations complete shadow inversion-style cleanup and reject updates from destroyed stylesheet managers; the latter prevents a delayed DOM-ready callback from recreating styles after Off, reproduced on Google Maps. Version upgrades must deliberately review these source guards and rerun lifecycle acceptance. See the [engine decision and sources](research/dark-mode.md).

Cross-origin CSS fetches require an active saved request, a top-frame extension sender and granted HTTP/HTTPS host access. Fetches omit credentials, reject non-CSS MIME types and all redirects before following a hop, time out after eight seconds, and cap decoded input at two MiB. The engine's own cross-origin restrictions remain in effect, including private/local destinations. Images and fonts are not fetched through this CSS bridge. Existing media pixels and canvas/WebGL scenes retain their native colors; SVG/CSS controls may be recolored semantically.

Small bundled CSS exceptions preserve sufficient text contrast on observed saturated branding surfaces. On Apple Maps only, an explicit On temporarily replaces its native `darkreader-lock` meta with a placeholder, restoring the same node on Off, Pause or forced colors. This themes controls without inverting map imagery. Foreign Dark Reader styles are left alone. An invalidated extension context with our old theme marker reports the need to refresh the page instead of pretending the old theme was removed.

The hosted runner’s Azure HTTP package mirror stalled for nearly five minutes on one font archive during final acceptance. CI switches only that mirror URL to Ubuntu’s HTTPS archive before installing browser system dependencies; package signatures and the required dependency set remain intact. Browser and npm caches remain unchanged.

Feature branches are verified through their pull requests; pushes to main verify merged changes. This avoids duplicate push/PR jobs downloading the same browser dependencies for the same update. Manual workflow scopes remain available for branch diagnostics.
