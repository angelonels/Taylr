# Foundation decisions

## 2026-10-21: Hide, first

The first release is a browser instrument: select an element, hide it, remember it on later visits, and reverse the action. The Arc research chat informed the interaction; the entire Boosts feature set is outside this milestone. Bulk matching of related elements and visual restyling are deferred.

TypeScript + Vite + Manifest V3 underpin the extension. The floating dock uses React and Tailwind at the user’s explicit request. React and Motion load only when the toolbar action is invoked; rule restoration and the picker controller remain framework-free. No server, account, telemetry, or remote data store is needed.

Rules belong to an exact origin (scheme, hostname, port), across its paths. Persistent site permission is requested in the original Chrome toolbar-action gesture. Dynamic content scripts restore rules on later visits. Storage stays local. The background worker is the single writer to avoid lost updates across tabs. Ordered profile broadcasts and storage events own live state; mutation replies confirm the operation and its created ID, but cannot overwrite a newer state. Initial reads are ignored if a newer live update arrived during initialization.

Hiding uses a stylesheet rather than removing nodes or rewriting inline styles. This preserves the site's DOM ownership, naturally handles newly inserted matching elements, and lets Restore reveal the site's own styling. It cannot prevent network loading and is not an ad blocker or privacy boundary.

Selectors favor unique semantic attributes (including product identity and landmark roles), then non-generated IDs and an exact structural path. UUID/React render identifiers cannot be persistence anchors. Combinations of semantic attributes precede child-link anchoring: a product identifier may also exist on a nested faceout, while its role identifies the card. Repeated cards can use their own unique link through `:has()` to preserve identity when neighbors are inserted. Recognized attribution parameters (UTM/click IDs and listing impression/search IDs) do not identify content; link selectors ignore them, preserve other query tokens with parameter boundaries, and retain fragments. Arbitrarily dropping a query string would merge different videos or content variants. A rule targets one element at creation. Structural paths can drift after a redesign or reordered list; they cannot promise to identify the same conceptual item forever. Broad matching is deferred rather than silently hiding related content. Shadow-root interiors and iframe interiors are outside this first milestone. A unique iframe element itself can be hidden from its parent page.

The floating dock replaces the side panel because reserving sidebar width changes responsive website layouts and can remove the intended target. Its smoked obsidian material, iris actions, coral selection stroke, isolation ring and inset rim keep it legible against unpredictable pages. React renders inside a Shadow DOM manual popover in the browser top layer, without reserving space. Visible Cancel/Done, Close, Undo and Escape make selection reversible. A grip supports bounded drag, edge switching and keyboard movement. Motion supplies interruptible drag values and release springs; reduced motion removes travel. Marketing belongs to a future landing page.

The old panel inferred “protected” when an active tab URL was unavailable. Chrome's activeTab grant belongs to an explicit extension invocation; switching tabs does not grant URL access. The action now uses the tab supplied by Chrome directly. Ordinary HTTPS pages such as LeetCode are not classified as protected. Website login/security challenges remain separate from Chrome-restricted pages and cannot establish application-level coverage.

Selection geometry follows layout changes. Parent traversal remembers the original child. Button glyphs/labels target the control by default; explicit Child refinement can still select its graphic. Only hierarchy refinement preserves an ancestor on a later click. Trusted native input is required for picker keyboard/pointer events and dock mutations; synthetic page events cannot create rules. Late replies cannot transfer Undo ownership to a new session.

Cancel/Done stops choosing more components. A Hide already initiated by a click still commits if the picker or dock is closed while saving; the saved rule remains reversible through Rules. Keyboard movement and activation are immediate, while pointer drag release can settle with a spring.

Incognito uses Chrome split mode with a separate `private-site:` namespace in session storage. Private rules survive reloads and new private tabs, but are memory-only and clear on browser restart or extension reload. Regular rules remain in local storage. Separate keys prevent the two workers from overwriting each other. Content scripts receive origin-scoped profile messages from the worker; session storage is not exposed to untrusted content contexts.

Undo records the exact ID returned by its own add request. Each injected controller belongs to its document and origin; profile broadcasts remain authoritative. Public-site tests refuse nonempty test profiles before taking ownership and cleaning up. Each case owns a disposable browser.

Automated testing moved to disposable Playwright Chromium at the user’s request. No personal-profile connection or permission broker remains. Exact-origin required host access exists only in a temporary test extension copy; production permission behavior is unchanged. The catalog selects modern sites and multiple component types for rendering/interaction difficulty, rather than using site count as a proxy for coverage.

## Component previews

Rules show cropped pixels of the component before hiding. Satori renders layouts supplied by an application; it cannot reproduce arbitrary third-party DOM, video, canvas, or fonts accurately. Native Chrome capture is appropriate here. Only the visible crop is encoded as a bounded WebP and stored with the rule; the full screenshot is transient in worker memory. The active tab, URL and originating document are checked around capture to avoid capturing a different page. Captures are rate-limited and time-bounded; unavailable, oversized, slow or denied capture falls back to the label. Storage pressure retries the new rule without its optional preview. Private previews use the same session-only partition as private rules.

The selected node must remain connected with unchanged bounds, scroll position and viewport throughout capture. Reflow, scrolling or zoom discards the optional preview without cancelling Hide; a crop from a former position could otherwise retain unrelated content.

A canvas displays decoded preview pixels so a site's restrictive img-src policy does not block a data-image element. The preview is a historical visual aid; it does not imply the site still has the same content. Partially visible components are marked accordingly. No screenshot leaves the device.
