# Public-site regression matrix

The catalog contains **37 sites and 111 component contracts**, selected for difficult rendering and interaction models: repeated cards, nested controls, custom-element hosts, canvas/WebGL/SVG workspaces, client rendering, sticky controls, media, and regional redirects. A case exists for its component behavior, not to inflate a website count.

The original reference/demo choices and Stack Overflow are removed. Security-only candidates Reddit, X, eBay, Etsy, Figma Community and The New York Times were replaced with accessible application workspaces. TikTok's regional denial was replaced with Excalidraw. The additional whiteboard, charting, creative coding, mathematics, map, flight-search and AI-catalog cases increase real application coverage while blocked popular sites remain visible as future regression candidates.

Each component independently follows **H01** visible target and retained content; **H02** precise Hide with no navigation or unintended control activation; **H03** Undo; **H04** attached-but-hidden reload and new-tab persistence; **H05** Restore across tabs and after reload; **H06** Escape. A missing node is not proof of hiding. Declared listing identities follow the selected item when the server reorders results. Retained components are independently chosen; preserving a descendant of the hidden target would be an invalid contract.

The shared chain protects feature invariants across different DOMs. It does not claim all behavior of the host applications is covered. Interactive contracts also retain meaningful state where available, including default sprite identity, unchanged search text, closed menus and editor zoom. Local fixture coverage separately checks concurrency, UUIDs and URL tracking IDs, card insertion, hostile typography, hierarchy round trips, hidden children, synthetic clicks, modifier and middle clicks, RTL placement, layout shifts, visible cancellation, focus recovery, denied access, stale responses, native zoom, viewport preservation, dock movement, reduced motion and visual rule previews.

## Latest acceptance

Acceptance on **22 October 2026**, Taylr **0.2.0**: all **111 contracts across 37 sites attempted** against the current build. **89 passed**, **22 externally blocked**, **0 unexplained failures**, **0 stale**, **0 unrun**. **29 sites passed all three contracts**. The 16 deterministic E2E cases and separate LeetCode action-access smoke also passed (106 total passes in the combined run). The strict Playwright command exits nonzero for the 22 blocked cases; they are not skipped or counted as feature passes.

The final independent review used the requested architecture, motion, animation-performance and ponytail audit/review skills. Its two findings—stale preview geometry and keyboard-triggered motion—were reproduced first, fixed and rereviewed with no remaining actionable findings. Build, type checking, formatting and production dependency audit passed.

Run `npm run test:report` to revalidate fingerprints and open the generated evidence. These results are a point-in-time compatibility record, not a guarantee against future website changes.

Commands, exact selectors, identities and expected state are in [testing.md](testing.md) and `tests/sites.json`. The generated `output/playwright/catalog-report.html` links each case's trace, checkpoints and screenshot. Generated evidence stays outside Git. Build/contract fingerprints mark superseded results stale. A site counts fully verified only when all three current contracts pass.

Access walls, regional unavailability, network failures, contract failures and extension defects are distinct. Blocked application pages are never feature passes. The opt-in live command returns nonzero for any incomplete contract, including external blocks; the aggregate report explains which case failed and which checkpoints completed. No login, CAPTCHA or paywall is bypassed.

Add or replace candidates when they contribute a difficult behavior. Expand their component contracts as new tools are implemented, preserving the reason each test exists.

LeetCode is an additional action-access smoke at `https://leetcode.com/problemset/`: distinguish false Chrome protection from a website security challenge. Problem-row, filter and search contracts remain planned until the application DOM is accessible in the isolated browser.
